## 실측으로 확인된 물리 사실 (재사용 가치 최상)

- **회전 바닥 8.9°**: 인코더 없는 개루프 시간 버스트 회전은 최소 지속 0.05 s +
  가속램프 절반 0.075 s 아래로 못 내려간다. 실주행 로그 438쌍: 10–20° 명령은
  1.01×로 정확, 2–4°는 2.33×, 0.8–2°는 2.12× 과회전.
- **모터 데드밴드**: `tank()`가 요청 duty를 `0.18 + 0.82×요청`으로 재매핑
  (`MOTOR_MIN_DUTY` 0.18). 회전속도 모델 `dps = TURN_DPS_AT_FULL × speed`는
  캘리브레이션 지점(0.35) 밖에서 틀림.
- **빈 슈트 vs 은색 공**: 밝기로 못 가른다(그늘진 은색 공 V≈128 ≈ 슈라우드).
  **깊이 게이트**가 정답: ROI 하단 도달 깊이 빈슈트 0.124–0.143 vs 실제 공
  최소 0.163 → 게이트 0.17로 빈 프레임 오검출 6/6→0/6, 공 282정답/0오답/14미검출.
- **광택 테이프**: 어둡기(V) 기반 마스크에서 벗어남 (Line Detection Probe 참조).
- **소실점 외삽의 함정**: 한 줄만 보일 때 근접밴드 fit을 지평선까지 161행
  외삽 → 기울기 오차 2.5× 증폭, +35° 유령 헤딩 생성. 두 줄(pair) 경로는 무관.
- **탐색 포화**: 스캔이 탐색 범위(±260px) 끝에서 멈춘 값은 측정값이 아니라
  "범위 밖" — 같은 값이 소수점까지 3회 반복되면 의심.
- **주석 프레임은 재분석 불가**: 검출 픽셀을 빨강으로 칠하면 dark mask가
  버림 → 원본(_raw.jpg) 병행 저장 필수.

## 미해결 결함 (당시 기준)

1. 공 6개 배출 기록인데 카메라2에 공 0개 — 호퍼/슈트/급지 어디서 막혔는지 물리 미확인
2. **골 포스트 검출 전멸** — 실제 터널은 흰 상자인데 주황/은색 포스트를 색으로 찾음
   → 거리 크로스체크·레인 검증 통째로 죽음. (개선안: 흰 직사각형을 형태로 검출)
3. 형상 인식이 0.40 m 후진 재시도 없이는 실패 (관측점 gap 4가 아직 틀림)
4. robot 더미 conf 0.47–0.80 — 미러 판정 전체가 단일 박스에 의존 (FIGURE_ANCHOR="robot")
5. blue 시뮬이 −60° 트위스트에서 중단 (red는 통과)
6. 인코더 없음 — 위 회전 바닥의 근원
7. 저속 회전속도 모델 오류 (데드밴드)
8. 매 런 설정 경고 2건 (LINE_ROI_TOP 무효, 시작 박스가 레인 밖 — 의도된 설계)

## 대회 후 구조 개선 제안 (원문 유지)

1. **IPM(역투영 매핑)** — 호모그래피로 조감도에서 격자 피팅, (x,y,θ) 동시 추정.
   소실점 외삽 자체를 제거. 최우선.
2. **확률적 측위 (파티클 필터/EKF)** — "인정 아니면 폐기"의 결정론 대신 가중치.
   SLAM은 틀린 도구(지도를 이미 앎).
3. solvePnP를 터널 보어에 (간격 0.30 m 기지)
4. 저속 회전 캘리브레이션으로 회전 바닥 8.9°→~5.1°
5. 휠 인코더 장착 (`_turn_encoders()` 등 코드 경로 이미 존재했음)
6. 흰 터널을 색이 아닌 형태·밝기 대비로 검출
